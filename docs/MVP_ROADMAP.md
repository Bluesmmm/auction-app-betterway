# MVP 路线图

## 1. MVP 目标

第一版目标不是做完整开放市场，而是在小范围真实试点中验证：

- 孩子是否愿意提交拍品、求购和参与积分竞拍。
- 家长是否能理解并完成监护、成交确认和交付确认。
- 活动管理员是否能承受审核与纠纷处理压力。
- 积分冻结、解冻、成交转移是否稳定无账务异常。
- 未成年人内容、隐私和禁售治理是否可控。
- 高风险生产场景是否能失败关闭，而不是依赖人工临场判断。
- 账号安全、管理员安全、备份恢复、发布迁移、供应商和全链路删除是否可控。

## 2. 试点规模

- 1-2 个拍卖社区。
- 30-100 个孩子。
- 平台团队人工盯审核、申诉、积分账本和交付异常。
- 不直接全量开放。

## 3. 开发阶段

### 阶段 0：设计冻结

产出：

- PRD。
- 技术架构。
- 数据模型。
- 状态机。
- 权限矩阵。
- 试点指标和暂停条件。
- 生产硬门槛清单。

验收：

- 产品、技术、运营和法务完成评审。
- 明确上线前不可缺失项。
- 明确时间裁决、文件访问、搜索可见性、日志导出、通知乱序和管理员误操作的阻断规则。
- 明确账号盗用、监护争议、管理员越权、备份恢复、迁移发布、供应商和全链路删除的阻断规则。

### 阶段 1：基础工程

范围：

- NestJS 项目骨架。
- PostgreSQL schema 和迁移。
- Prisma 普通模型。
- 关键路径 SQL/Query Builder 约定。
- Redis 和 BullMQ。
- Web 管理后台骨架。
- 微信小程序骨架。
- 环境配置和日志基础设施。
- 服务端/数据库时间源约定。
- 结构化日志脱敏基础设施。
- 对象存储私有访问和签名 URL 服务。
- 管理员 MFA 和敏感操作二次验证基础设施。
- 备份恢复、迁移回滚和密钥轮换演练脚本。

验收：

- dev/staging 环境可部署。
- API、worker、后台、小程序能完成基本联通。
- 数据库迁移可重复执行。
- 关键 API 响应包含服务端裁决时间和目标版本。
- 日志扫描不出现手机号、地址、对象 key、签名 URL 或快递信息明文。
- 管理员账号未启用 MFA 时不能进入后台高危功能。
- staging 可完成一次迁移回滚和一次恢复演练。

### 阶段 2：账号、家长与社区

范围：

- 微信登录。
- access token + refresh token。
- 家长手机号和监护声明。
- 孩子档案。
- 主/副监护人绑定。
- 监护争议冻结模式。
- 家长控制项。
- 社区创建申请。
- 邀请码。
- 社区加入申请、家长确认、管理员审核。
- 邀请码并发消耗和使用次数上限。
- 同一主监护人名下孩子关系识别。
- 社区规则版本、名册核验和成年人伪装风险信号。

验收：

- 孩子无家长绑定不能发布、出价、成交。
- 加入社区必须经过邀请码、家长确认和管理员审核。
- 一个孩子最多两个家长，一个家长默认最多三个孩子。
- 并发使用最后一个邀请码名额时，最多只有一个加入申请成功消耗名额。
- 家长新设备、异常登录或敏感操作未二次验证时，不能导出、注销、确认成交或修改权限。
- 监护争议未解决时，孩子不能发布、出价、确认交易、导出或注销。
- 疑似成年人伪装、异常加入、诱导联系和跨社区异常行为会限制账号并进入平台复核。

### 阶段 3：内容、文件与审核

范围：

- 图片本地压缩和临时私有上传。
- 拍品提交。
- 求购提交。
- 求购响应。
- 第三方内容安全 API。
- OCR、二维码/条码识别和图片元数据检查。
- 规则引擎。
- 人工审核后台。
- 内容版本机制。
- 审核通过后转正式存储。
- 下架和拒绝原因。
- 审核双审、抽检和审核员质量记录。
- 商品安全风险标签。
- 恶意文件上传防护。

验收：

- 未审核内容不公开展示。
- 阶段 3 审核通过只产生可公开展示的内容版本和正式私有文件，不创建可出价的拍卖场次。
- 拍品必须满足 4 张图。
- AI 风险标签可在后台查看。
- 所有拍品、求购、响应必须人工审核后展示。
- 已上架内容修改公开字段后必须重新审核，新版本通过前孩子端不可见。
- 内容安全 API 故障、超时或不可解析时不能自动上架。
- 审核后台展示原图、OCR 文本、二维码检测结果、版本 diff 和历史违规上下文。
- 阶段 3 人工审核后台只覆盖内容审核队列、审核详情和审核动作，不提前实现阶段 8 的完整治理看板、抽检看板或投诉联动。
- 已拒绝、未审核、下架或删除图片通过旧签名 URL 访问时被拒绝。
- 高风险内容、首次发布、被投诉账号和儿童隐私命中进入双审或平台抽检。
- 伪装 MIME、恶意 SVG、超大图片、压缩炸弹和带 EXIF 隐私图片被拒绝或清理。
- 召回商品、破损电池、磁力珠、小零件误食风险和尖锐零件可被标记并下架。

第一轮实施顺序：

1. 更新 Prisma schema 和 migration，补齐 `content_version_media` 以及必要审核字段、索引和约束。
2. 先写 contract/integration tests，覆盖提交、审核、编辑绕审、文件访问和高风险失败关闭。
3. 实现服务端 API：临时文件上传、提交/编辑拍品、审核任务处理、人工审核动作和孩子端详情读取。
4. 接入最小后台页面：内容审核队列、审核详情和 approve/reject/escalate 动作。
5. 接入最小小程序入口：拍品提交和详情读取；搜索、排序、收藏和首页列表留到阶段 7。
6. 第一轮只落拍品 `item` 闭环；`ContentTargetType` 可保留求购、响应和头像扩展位，但不提前实现求购/响应表、UI 或状态机。

第一轮供应商边界：

- 先使用可控 fake provider 和规则引擎验证系统契约，不接真实第三方内容安全供应商。
- fake provider 必须可稳定模拟 `low`、`medium`、`high`、`severe`、失败、超时、不可解析、OCR 联系方式命中、二维码/条码命中、EXIF 隐私命中和恶意文件拒绝路径。
- 真实第三方内容安全、OCR、二维码/条码和图片安全供应商接入留到阶段 3 后半段或阶段 9 试点前验证，并复用同一套 contract tests。

第二轮实施顺序：

1. 新增 `wanted_posts` 和 `wanted_responses` 业务事实表，并复用 `content_versions`、`content_version_media` 与 `moderation_tasks`。
2. 求购和求购响应提交同样先创建事实与待审核内容版本，不自动公开、不创建拍卖场次。
3. 求购和求购响应第一版同样要求 4 张临时私有图片，先用同一 fake provider 和人工审核闭环验证文件、版本和失败关闭契约。
4. 审核后台队列从 item-only 扩展为按 `target_type` 展示拍品、求购和响应，仍只提供队列、详情、approve/reject/escalate/retry。
5. 孩子端补最小求购提交、响应提交和详情读取壳；搜索、排序、收藏、首页列表仍留到阶段 7。
6. 第二轮仍不接真实第三方内容安全供应商、不实现阶段 8 抽检/投诉/治理大屏、不创建阶段 5 拍卖场次。

第三轮实施顺序：

1. 持久化 AI/provider 审核证据，记录 provider 状态、风险标签、OCR 文本、二维码/条码检测、图片元数据发现和失败原因。
2. 持久化人工审核记录，记录审核人、审核时间、决策、原因和对应内容版本。
3. 审核详情展示短期原图授权、AI 证据、规则标签和上一公开版本与当前待审版本 diff。
4. 高风险和严重风险仍不能由活动管理员单人批准；第三轮只补证据和可解释性，不实现完整双审工作台。
5. 第三轮继续使用 fake provider，不接真实第三方供应商，不开放搜索/列表，不创建拍卖场次，不提前实现阶段 8 治理看板。

第四轮实施顺序：

1. 审核原图短期授权 `content_review_original` 必须经过文件访问网关二次校验，校验管理员身份、社区 scope、审核任务状态、grant purpose 和媒体绑定关系。
2. 高风险和严重风险内容由活动管理员升级后，平台管理员可以将升级内容收口为 `blocked` 或 `rejected`；平台批准高风险内容仍留到完整双审/平台复核链路，不在第四轮开放。
3. fake provider 补充商品安全风险标签：召回商品、破损电池、磁力珠、小零件误食风险和尖锐零件。
4. 审核详情补同一孩子/社区近期 rejected、escalated、blocked 内容摘要，作为历史违规上下文，不实现阶段 8 治理大屏。
5. 增加 Stage 3 readiness 检查脚本，将审核证据、原图授权网关、高风险收口、商品安全标签和历史上下文纳入验证门槛。

第五轮收口与审查：

1. 以 `1aa4b24...feature/stage3-content-review` 作为阶段 3 review 范围，按 Standards 和 Spec 两轴审查已实现的四轮内容审核闭环。
2. 第五轮修复平台复核访问缺口：平台管理员既然负责升级内容兜底收口，就必须能按目标社区打开审核队列、审核详情、获取 `content_review_original` 原图授权，并执行 retry、下架或取消等治理动作。
3. 普通 `approve` / `reject` / `escalate` 人工审核入口仍只允许具备目标社区 scope 的活动管理员；平台管理员关闭高风险内容必须走 `platformReviewModerationTask`，且本阶段仍不开放平台批准高风险内容公开展示。
4. 第五轮验证门槛包括 Stage 3 contract tests、integration flow、runtime shell、readiness 静态检查、typecheck 和完整 build；没有这些验证证据，不得声明阶段 3 可提交或可合并。
5. 阶段 3 收口后仍保留明确边界：不接真实第三方内容安全供应商，不开放搜索/列表/排序/收藏，不创建拍卖场次，不实现阶段 8 完整抽检、投诉、双审质量看板。

第六轮合并前验收：

1. 第六轮只做 merge-readiness，不扩展阶段 3 功能范围。
2. 后台调用链必须和后端审核契约一致：既然后端暴露 `platformReviewModerationTask`，Web 管理后台也必须提供 `platform-review` 调用入口，让平台管理员能对已升级内容执行 `block` 或 `reject` 收口。
3. readiness 检查必须覆盖后台平台收口 API 和页面动作，防止只保留后端路由、丢失后台可操作入口。
4. 合并前仍以 `stage3:verify`、完整 build 和 `git diff --check` 作为最低验证证据。

### 阶段 4：积分账本

范围：

- 每个孩子一个全局积分账户。
- 首次绑定初始积分发放。
- 管理员批量发放、扣减、纠错。
- 家长积分申请。
- 余额快照。
- 不可变账本流水。
- 账本校验任务。

验收：

- 积分不可充值、提现或系统外转让。
- 管理员调整必须有原因和审计日志。
- 快照与流水可重算校验。
- 试点前账本异常数为 0。

### 阶段 5：拍卖核心闭环

范围：

- 拍卖场次创建。
- 固定结束时间。
- 出价。
- PostgreSQL 事务和行级锁。
- 锁等待超时、死锁重试和未知结果处理。
- 当前最高出价冻结。
- 被超越解冻。
- 1 分钟内撤销出价。
- 自买自卖和同家庭互拍拦截。
- 流拍。
- 延迟队列结算。
- 定时扫描兜底。
- WebSocket 出价推送。

验收：

- 并发出价不会产生重复最高价或负余额。
- 出价成功后积分冻结准确。
- 被超越后旧冻结释放。
- 拍卖结束结算幂等。
- 无人出价自动流拍。
- 卖家孩子、同一主监护人名下孩子和被限制账号不能出价。
- 起拍积分、最小加价和出价金额的非法值被数据库或服务层拒绝。
- 客户端时间错误、服务端锁等待超时、死锁和网络重试不会造成错误成交或重复冻结。
- Redis/BullMQ 故障时，PostgreSQL 事实不受影响，到期拍卖由扫描任务补偿或进入待结算处理。

### 阶段 6：成交、交付与申诉

开工口径：

- 阶段 5 已经承载拍卖结束后 `transactions` 创建、买卖双方主监护人成交确认、交付确认、成交确认超时、交付超时和管理员争议裁决的第一版账务闭环。
- 阶段 6 不从零重做成交交付链路，而是在现有交易、监护人决策、冻结积分、超时 worker 和管理员裁决机制上做收口与补缺。
- 阶段 6 的重点是交付方式、申诉/平台复核证据链、主/副监护人冲突规则显式化、孩子/家长/管理员入口契约、readiness 验证和文档对齐。
- 阶段 6 第一版只开放指定交付点和家长自行约定交付；快递交付保留扩展位但 API/UI 必须失败关闭。
- 交付方式由卖方主监护人在成交确认阶段先提出，买方主监护人的成交确认同时表示接受；孩子不能选择交付方式，成交确认完成后交付方式锁定。
- 原 Stage 5 的并行成交确认语义在 Stage 6 收口为“卖方成交确认提案 -> 买方接受或拒绝”的顺序契约。
- Stage 6 必须补强 `guardian_decisions` 证据快照，持久化决策当时的买卖侧、孩子档案、监护人角色、交易版本和原因；不能只依赖事后查询当前监护关系解释历史决策。
- 副监护人不能确认成交、接受交付方式、确认交付或覆盖主监护人拒绝；副监护人只能提交交易申诉、补充说明或触发平台复核线索。
- 家长提出成交确认提案、接受或拒绝成交、交付确认或交付拒绝都必须经过敏感操作二次验证；普通交易申诉文本和申诉图片附件提交不强制二次验证，但必须校验目标交易有效监护关系。
- 交易申诉使用独立 `appeals` 事实，不复用 `guardian_disputes`；只有申诉暴露真实监护关系冲突时才另行打开监护争议冻结。
- 普通交易申诉先进入目标社区活动管理员队列；升级、跨社区、高风险、管理员被投诉或长期冻结时进入平台管理员复核。
- 交易申诉第一版允许最多 4 张申诉图片附件，但不开放视频、音频、PDF、压缩包、聊天记录导出文件或任意文件；附件必须走私有上传、安全扫描、隐私清理和短期授权。
- 申诉图片附件复用 Stage 3 的 `MediaAsset`、临时私有上传、内容安全 provider 和私有文件授权网关，但不创建 `ContentVersion`、`ModerationTask` 或孩子端公开内容入口。
- 指定交付点是社区级治理资源，由具备社区 scope 的活动管理员维护、平台管理员兜底；禁用不删除历史证据。

范围：

- 拍卖结束后创建交易。
- 卖方主监护人提出成交确认提案，买方主监护人接受或拒绝。
- 监护人决策流水和主/副监护人冲突处理。
- 成交确认、成交拒绝、交付确认和交付拒绝的敏感操作二次验证。
- 48 小时确认超时处理。
- 交付方式：指定交付点、家长自行约定；快递只保留扩展位。
- 指定交付点创建、编辑和禁用。
- 双方家长交付确认。
- 72 小时交付超时转管理员。
- 管理员争议处理：退回买家、转给卖家、继续冻结。
- 申诉和平台复核。
- 申诉图片附件上传、扫描、短期授权和失败关闭。

实施顺序：

1. 第一轮只做 Schema、契约和服务层状态机：补齐 `guardian_decisions` 证据字段、`delivery_points`、`delivery_records`、`appeals`、`appeal_attachments`、必要枚举和数据库约束，并实现成交确认提案、买方接受或拒绝、交付确认、交付方式校验、申诉创建、申诉图片附件扫描和交易裁决收口。
2. 第一轮验证：先写 schema/contract/integration tests，新增第一轮 `stage6:verify` 门禁，覆盖 schema、service、申诉附件扫描、文件授权、typecheck 和 build。
3. 第二轮 API 与权限：暴露家长交易动作、管理员交付点管理、申诉处理和附件短期授权，并接入敏感操作二次验证、管理员 MFA、社区 scope 和文件访问网关。
4. 第二轮最小端侧入口：补小程序家长交易动作和申诉入口，补后台交付点、申诉队列和平台复核入口，不提前扩展 Stage 7 通知/搜索体验或 Stage 8 治理大屏。
5. 第二轮验证收口：扩展 `scripts/stage6/verify-stage6.mjs`，覆盖 controller、worker 补偿、端侧 shell、typecheck 和 build。

第一轮测试矩阵：

- Schema/contract：验证 `guardian_decisions` 证据字段、`delivery_points`、`delivery_records`、`appeals`、`appeal_attachments`、交付方式枚举、申诉状态枚举、索引、外键、唯一约束和最多 4 张申诉图片附件约束。
- Migration 策略：第一轮 migration 必须 additive/backfill-safe；新表可直接创建，现有表只新增字段、索引和约束，不删除、不重命名现有列。`guardian_decisions` 新证据字段允许历史行为空，但 Stage 6 新写入决策必须填全；best-effort backfill 不得因 Stage 5 历史证据不完整阻断部署。
- 成交确认提案：卖方主监护人可提出有效交付方式；买方主监护人不能在有效提案缺失时先确认；买方接受后进入 `pending_delivery_confirm`；任一方拒绝取消交易并释放买家冻结积分。
- 主/副监护人边界：副监护人不能确认成交、接受交付方式、确认交付或覆盖拒绝；副监护人只能提交交易申诉、补充说明或触发复核线索。
- 敏感操作二次验证：成交确认提案、成交接受、成交拒绝、交付确认和交付拒绝缺少有效二次验证时必须失败关闭，不改变交易状态、冻结积分或账本。
- 交付方式校验：`designated_point` 必须绑定目标社区 active 交付点；disabled 交付点不能被新交易选择；`guardian_arranged` 必须满足社区和双方孩子家长控制项；`courier` 在第一版必须失败关闭。
- 交付确认与积分不变量：成交确认前冻结持续 active；交付任一方拒绝进入 `disputed` 且冻结不释放；双方交付确认后买家冻结转给卖家；账本流水、冻结状态和交易状态可重放解释。
- 申诉事实：买卖双方有效监护人可提交交易申诉；无关家长不能提交；普通申诉不默认打开 `guardian_disputes` 或冻结孩子全部参与能力；活动管理员只能处理自己社区申诉，平台管理员处理升级复核。
- 申诉图片附件：每个申诉最多 4 张私有图片；视频、音频、PDF、压缩包、聊天记录导出文件和任意文件被拒绝；不可解析、疑似恶意、命中地址电话二维码儿童隐私或严重风险时拒绝或升级平台复核。
- 文件访问授权：申诉图片附件只能由提交申诉的家长、目标社区活动管理员和平台管理员通过 `appeal` purpose 短期授权读取；过期、错误 purpose、错误 grantee、被拒绝或 revoked 附件必须失败关闭。
- 回归门禁：第一轮 `stage6:verify` 必须运行 Stage 6 schema/contract/integration tests、申诉附件扫描与文件授权 tests、Stage 5 交易/worker 关键回归、`npm run typecheck`、`npm run build` 和 `git diff --check`。

第二轮交付计划：

- 家长交易 API：成交确认提案、成交接受、成交拒绝、交付确认、交付拒绝、交易详情读取和交易申诉提交；所有改变交易状态的动作必须接入敏感操作二次验证。
- 管理员交付点 API：具备社区 scope 的活动管理员可创建、编辑和禁用本社区指定交付点；平台管理员可跨社区兜底；禁用不删除历史证据。
- 管理员申诉 API：活动管理员读取自己社区申诉队列、查看申诉详情、记录处理意见、执行允许的交易裁决或升级平台；平台管理员读取升级队列并执行平台复核收口。
- 附件授权 API：提交申诉的家长、目标社区活动管理员和平台管理员可按 `appeal` purpose 获取短期申诉图片授权；错误 purpose、错误 grantee、过期、revoked 或未接受附件必须失败关闭。
- 小程序最小入口：家长交易详情、卖方成交确认提案、买方接受或拒绝、交付确认或拒绝、提交交易申诉、上传最多 4 张申诉图片附件；不做 Stage 7 通知中心、搜索、收藏或复杂体验优化。
- 后台最小入口：指定交付点列表和维护、交易申诉队列、申诉详情、附件查看、处理意见、升级平台、交易裁决入口；不做 Stage 8 完整治理大屏、危险操作预览、双人复核或导出。
- Worker/补偿入口：保留 Stage 5 成交确认超时和交付超时 worker 语义；第二轮只补 API/UI 后的回归验证，不把结算或超时逻辑迁移到读请求。

第二轮测试矩阵：

- Controller 契约：家长交易 API、交付点 API、申诉 API 和附件授权 API 必须从 Bearer token 派生 actor，不接受客户端传入的 user/admin/guardian 身份覆盖。
- 权限与 scope：活动管理员不能跨社区管理交付点、读取申诉、查看附件或裁决交易；平台管理员可处理升级申诉；无关家长不能读取交易详情、提交申诉或获取附件授权。
- 敏感操作二次验证：controller 层必须拒绝缺少有效挑战的成交确认提案、成交接受、成交拒绝、交付确认和交付拒绝；普通申诉提交不要求二次验证但必须校验有效监护关系。
- 文件授权网关：`appeal` purpose 授权必须覆盖提交家长、目标社区活动管理员和平台管理员路径，并拒绝错误 purpose、错误 grantee、过期 grant、revoked 附件、rejected 附件和跨社区管理员。
- 小程序 shell：页面只调用 Stage 6 API 契约，不在本地推导交易权限、交付方式可选项或申诉可见性；失败关闭状态必须能展示为不可操作。
- 后台 shell：交付点维护和申诉处理入口必须使用 Stage 6 API；活动管理员视图限定本社区，平台管理员视图限定升级/复核职责。
- 回归门禁：第二轮 `stage6:verify` 必须覆盖 Stage 6 controller tests、端侧 shell tests、申诉附件授权 tests、Stage 5 交易/worker 关键回归、`npm run typecheck`、`npm run build` 和 `git diff --check`。

验收：

- 成交确认前积分持续冻结。
- 任一方家长拒绝可取消并解冻。
- 买方主监护人不接受卖方提出的交付方式时，必须通过拒绝成交收口，不能在交易内反复协商改写交付方式。
- 禁用的指定交付点不能被新交易选择，已绑定历史交易的交付点证据仍可追溯。
- 双方交付确认后积分转移。
- 未通过敏感操作二次验证的家长成交确认、成交拒绝、交付确认或交付拒绝必须失败关闭，不得改变交易状态或积分冻结。
- 管理员处理只影响平台内状态和积分，不裁决线下赔偿。
- 交易申诉只能影响对应交易的证据、状态和冻结积分收口，不默认冻结孩子全部参与能力。
- 申诉图片附件不能公开展示；未通过扫描、不可解析、疑似恶意、命中地址电话二维码儿童隐私或严重风险时，必须拒绝或升级平台复核，不能直接暴露给活动管理员。
- 活动管理员只能处理自己社区的交易申诉；平台管理员处理升级申诉、跨社区异常、管理员被投诉、疑似监护冲突、严重风险或长期冻结。
- 主监护人和副监护人冲突时，系统按主监护人优先或管理员处理规则收口。
- 副监护人与主监护人意见冲突不能直接改变交易状态；只有确认存在真实监护关系争议时，才另行打开 `guardian_disputes` 并冻结相关能力。

## 4. 测试重点

### 4.1 状态机测试

覆盖：

- 草稿到审核。
- 审核通过到待开始。
- 待开始到拍卖中。
- 拍卖中到待家长确认。
- 待家长确认到待交付确认。
- 待交付确认到已完成。
- 任意异常路径到已取消、流拍或已下架。
- 社区/分类暂停时，未开始、拍卖中、待确认、待交付场次按规则收口。
- 注销申请遇到活跃拍卖、有效冻结或未结申诉时被阻断。
- 客户端时间快进/回拨不能影响撤销窗口、拍卖结束、48 小时确认和 72 小时交付超时。
- 服务端时间异常或结算时间不确定时，场次进入待结算处理而不是自动成交。

### 4.2 积分账本测试

覆盖：

- 初始发放。
- 出价冻结。
- 被超越解冻。
- 撤销解冻。
- 成交完成转移。
- 取消退回。
- 管理员调整。
- 冲正记录。
- 快照与流水重算一致。

### 4.3 并发测试

覆盖：

- 同一拍品多人同时出价。
- 同一孩子对多个拍品同时出价。
- 出价和拍卖结算同时发生。
- 撤销和新出价同时发生。
- 队列重复触发结算。
- 最后一个邀请码名额被多人同时使用。
- outbox 事件重复领取、worker 崩溃和租约过期后重试。
- 出价、撤销、结算、确认和交付同时触发锁等待、死锁和重试耗尽。
- Redis/BullMQ 停止后，扫描任务从 PostgreSQL 补偿到期拍卖。

### 4.4 权限测试

覆盖：

- 未绑定家长的孩子不能发布、出价、成交。
- 未加入社区不能浏览、搜索、出价。
- 家长只能管理自己的孩子。
- 活动管理员只能处理自己社区。
- 平台管理员可复核全平台事项。
- 卖家孩子不能对自己的拍品出价。
- 同一主监护人名下孩子默认不能互拍。
- 账号、社区成员、分类或平台暂停时，服务端拒绝对应写操作。
- 副监护人不能覆盖主监护人的有效拒绝或关键限制。
- 搜索、列表、收藏、通知跳转和签名 URL 访问都必须服务端回源校验权限。
- 缓存命中或搜索索引命中不能绕过当前下架、暂停、成员移除和注销状态。
- 活动管理员不能跨社区访问列表、详情、搜索、导出、审核和审计。
- 管理员未 MFA 或未通过复核时不能执行高危操作。
- 家长未通过敏感操作挑战时不能导出、注销、确认成交或修改孩子权限。

### 4.5 隐私与内容测试

覆盖：

- 图片出现儿童、人脸、姓名、地址、二维码时拦截或进入高风险。
- 禁售品类拦截。
- 文本联系方式拦截。
- 未审核图片不可公开访问。
- 孩子端不可见原价金额、家长手机号、地址、快递信息。
- 已上架内容编辑后必须生成新版本并重新审核。
- 高风险和严重风险不能由活动管理员单人放行。
- OCR、二维码/条码、图片元数据和联系方式变体命中时拦截或升级。
- 日志、通知 payload、导出文件和审计摘要不包含敏感明文。
- 高风险审核样本经过双审或平台抽检。
- 审核误放、误拒和复核改判进入质量指标。
- 商品安全风险样本被拦截或下架。

### 4.6 文件、搜索与通知测试

覆盖：

- 未审核、拒绝、下架、删除和权限不匹配文件的旧签名 URL 被拒绝。
- 签名 URL 过期、文件策略版本变化、注销和下架后不能继续访问。
- 搜索索引延迟、缓存陈旧、内容下架和成员移除后回源过滤。
- WebSocket 和通知乱序、重复、延迟时，客户端只展示刷新后的服务端状态。
- 从通知进入详情页、页面恢复前台、WebSocket 重连后强制 REST 拉取最新状态。

### 4.7 生产 edge case 回归

覆盖：

- 自买自卖、同家庭互拍、刷分和求购响应绕过互拍限制。
- 主/副监护人对成交确认和交付确认做出冲突决定。
- 社区暂停、分类暂停、暂停出价、暂停成交结算对活跃拍卖和冻结积分的影响。
- 内容安全 API 超时、失败、重复回调和返回不可解析。
- 账号限制、成员移除和注销申请遇到未完成交易或有效冻结。
- 起拍积分、最小加价、出价金额为 0、负数或超过平台上限。
- 管理员已有出价后调整结束时间的通知、次数和审计约束。
- 日志脱敏扫描、导出文件过期、管理员影响预览过期后重算。
- 事务结果 unknown、幂等键复用不同 payload、客户端重复点击和弱网重试。
- 家长账号疑似被盗后，会话撤销、敏感操作阻断和家长通知。
- 管理员账号疑似被盗后，MFA 失败、scope 越权、双人复核和高危操作拦截。
- 监护关系争议后，孩子档案冻结、交易收口和导出/注销阻断。
- 成年人伪装孩子、诱导联系方式和异常社区加入。
- 微信订阅消息不可达时，站内待办仍能推动关键流程。
- WebSocket 旧房间权限在成员移除、解绑和封禁后失效。
- 恶意投诉攻击、刷浏览/收藏/热门和审核员疲劳误放。
- 数据库备份恢复后，账本重算、冻结核对、outbox 去重和搜索重建。
- 灰度发布时旧 API、旧 worker、新 schema 的兼容和回滚。
- 注销后主库、搜索索引、对象存储、导出文件、缓存、通知和备份保留策略覆盖。

## 6. 暂停条件

必须设为硬门槛：

- 严重儿童隐私泄露：立即暂停相关社区或全平台发布/展示。
- 积分账本异常：立即暂停出价、成交和积分转移。
- 投诉、申诉、取消率超过阈值：暂停扩容，进入复盘。
- 审核积压严重：暂停新发布或限制发布频率。
- 违规物品高发：加严规则或暂停相关分类。
- 未审核文件访问、搜索权限泄露、日志/导出敏感字段命中：立即暂停相关能力并复盘。
- 锁等待/死锁或 unknown 结果异常升高：暂停出价和结算，进入账本校验。
- 管理员账号异常、MFA 覆盖不达标或高危操作越权：暂停后台高危能力。
- 账号盗用、成年人伪装、监护争议高发或严重儿童安全商品漏放：暂停相关社区或全平台发布/出价。
- 备份恢复演练出现账本差异、outbox 重放或迁移回滚失败：不得上线。
- 供应商越权、敏感字段发送越界或第三方数据处理风险未关闭：暂停对应供应商能力。
- 删除/匿名化任务失败或导出文件过期清理失败：暂停数据导出和注销完成确认。

所有暂停和恢复都必须由平台管理员记录原因。

## 7. 上线前检查清单

- PRD、架构、数据模型完成评审。
- 法务完成用户协议、隐私政策、儿童信息保护规则复核。
- 所有核心状态机有测试。
- 积分账本并发和重算测试通过。
- Web 管理后台危险操作全留痕。
- 未审核图片无法公开访问。
- 内容版本、监护人决策、治理开关、outbox 租约和邀请码并发测试通过。
- 服务端时间裁决、锁等待/死锁、Redis/BullMQ 降级、通知乱序、搜索回源、文件签名访问和日志导出脱敏测试通过。
- 管理员危险操作影响预览、二次确认和过期重算演练完成。
- 家长敏感操作二次验证、管理员 MFA、RBAC scope、监护争议冻结和会话撤销测试通过。
- 备份恢复、账本重算、outbox 去重、搜索重建、迁移回滚和灰度兼容演练通过。
- 供应商数据最小化、密钥轮换、降级策略和调用审计完成。
- 全链路删除/匿名化任务覆盖主库、搜索索引、对象存储、导出文件、缓存和通知。
- 订阅消息模板配置完成。
- 暂停开关演练完成。
- 试点社区、管理员和家长说明材料准备完成。
