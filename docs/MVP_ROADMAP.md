# MVP 路线图

## 1. MVP 目标

第一版目标不是做完整开放市场，而是在小范围真实试点中验证：

- 孩子是否愿意提交拍品、求购和参与积分竞拍。
- 家长是否能理解并完成监护、成交确认和交付确认。
- 活动管理员是否能承受审核与纠纷处理压力。
- 积分冻结、解冻、成交转移是否稳定无账务异常。
- 未成年人内容、隐私和禁售治理是否可控。

## 2. 试点规模

- 1-2 个拍卖社区。
- 30-100 个孩子。
- 平台团队人工盯审核、申诉、积分账本和交付异常。
- 不直接全量开放。

## 3. 开发阶段

### 阶段 0：设计冻结

产出：

- PRD。
- 技术架构。
- 数据模型。
- 状态机。
- 权限矩阵。
- 试点指标和暂停条件。

验收：

- 产品、技术、运营和法务完成评审。
- 明确上线前不可缺失项。

### 阶段 1：基础工程

范围：

- NestJS 项目骨架。
- PostgreSQL schema 和迁移。
- Prisma 普通模型。
- 关键路径 SQL/Query Builder 约定。
- Redis 和 BullMQ。
- Web 管理后台骨架。
- 微信小程序骨架。
- 环境配置和日志基础设施。

验收：

- dev/staging 环境可部署。
- API、worker、后台、小程序能完成基本联通。
- 数据库迁移可重复执行。

### 阶段 2：账号、家长与社区

范围：

- 微信登录。
- access token + refresh token。
- 家长手机号和监护声明。
- 孩子档案。
- 主/副监护人绑定。
- 家长控制项。
- 社区创建申请。
- 邀请码。
- 社区加入申请、家长确认、管理员审核。
- 邀请码并发消耗和使用次数上限。
- 同一主监护人名下孩子关系识别。

验收：

- 孩子无家长绑定不能发布、出价、成交。
- 加入社区必须经过邀请码、家长确认和管理员审核。
- 一个孩子最多两个家长，一个家长默认最多三个孩子。
- 并发使用最后一个邀请码名额时，最多只有一个加入申请成功消耗名额。

### 阶段 3：内容、文件与审核

范围：

- 图片本地压缩和临时私有上传。
- 拍品提交。
- 求购提交。
- 求购响应。
- 第三方内容安全 API。
- 规则引擎。
- 人工审核后台。
- 内容版本机制。
- 审核通过后转正式存储。
- 下架和拒绝原因。

验收：

- 未审核内容不公开展示。
- 拍品必须满足 4 张图。
- AI 风险标签可在后台查看。
- 所有拍品、求购、响应必须人工审核后展示。
- 已上架内容修改公开字段后必须重新审核，新版本通过前孩子端不可见。
- 内容安全 API 故障、超时或不可解析时不能自动上架。

### 阶段 4：积分账本

范围：

- 每个孩子一个全局积分账户。
- 首次绑定初始积分发放。
- 管理员批量发放、扣减、纠错。
- 家长积分申请。
- 余额快照。
- 不可变账本流水。
- 账本校验任务。

验收：

- 积分不可充值、提现或系统外转让。
- 管理员调整必须有原因和审计日志。
- 快照与流水可重算校验。
- 试点前账本异常数为 0。

### 阶段 5：拍卖核心闭环

范围：

- 拍卖场次创建。
- 固定结束时间。
- 出价。
- PostgreSQL 事务和行级锁。
- 当前最高出价冻结。
- 被超越解冻。
- 1 分钟内撤销出价。
- 自买自卖和同家庭互拍拦截。
- 流拍。
- 延迟队列结算。
- 定时扫描兜底。
- WebSocket 出价推送。

验收：

- 并发出价不会产生重复最高价或负余额。
- 出价成功后积分冻结准确。
- 被超越后旧冻结释放。
- 拍卖结束结算幂等。
- 无人出价自动流拍。
- 卖家孩子、同一主监护人名下孩子和被限制账号不能出价。
- 起拍积分、最小加价和出价金额的非法值被数据库或服务层拒绝。

### 阶段 6：成交、交付与申诉

范围：

- 拍卖结束后创建交易。
- 买卖双方家长并行确认。
- 监护人决策流水和主/副监护人冲突处理。
- 48 小时确认超时处理。
- 交付方式：指定交付点、家长自行约定、快递。
- 双方家长交付确认。
- 72 小时交付超时转管理员。
- 管理员争议处理：退回买家、转给卖家、继续冻结。
- 申诉和平台复核。

验收：

- 成交确认前积分持续冻结。
- 任一方家长拒绝可取消并解冻。
- 双方交付确认后积分转移。
- 管理员处理只影响平台内状态和积分，不裁决线下赔偿。
- 主监护人和副监护人冲突时，系统按主监护人优先或管理员处理规则收口。

### 阶段 7：通知、搜索与体验

范围：

- 小程序内通知中心。
- 微信订阅消息。
- 分层通知和家长配置。
- 搜索已加入社区内容。
- 分类筛选。
- 关键词相似度匹配。
- 最新、即将结束、出价最多、热门排序。
- 收藏/关注拍品。

验收：

- 孩子只收到轻量动态。
- 家长收到成交、交付、违规、申诉和积分异常。
- 未加入社区内容不可搜索。
- 热门排序不使用个人画像。

### 阶段 8：后台治理与试点看板

范围：

- 社区审核。
- 成员审核。
- 拍品/求购/响应审核队列。
- 违规下架。
- 账号限制。
- 信用记录。
- 数据导出。
- 注销申请。
- 试点指标看板。
- 暂停开关。
- 平台、社区、分类级治理开关及收口策略。

验收：

- 活动管理员可处理一线问题。
- 平台管理员可复核严重违规和全平台限制。
- 所有危险操作留痕。
- 支持暂停新发布、出价、成交结算、单社区、单分类。
- 暂停后活跃拍卖、冻结积分、待确认交易和审核中内容都有明确收口结果。

### 阶段 9：试点前验证

范围：

- 单元测试。
- 状态机测试。
- 积分账本测试。
- 并发出价测试。
- 端到端流程测试。
- 权限测试。
- 内容审核测试。
- 隐私检查。
- 生产 edge case 回归。
- 运营演练。

验收：

- 核心 happy path 全通过。
- 取消、撤回、流拍、下架、申诉等异常路径全通过。
- 账本校验无异常。
- 严重隐私泄露风险用例被拦截。
- 管理员能执行暂停和恢复流程。
- 自买自卖、同家庭互拍、内容修改绕审、监护人冲突、邀请码并发、outbox 重复消费、注销阻断等 edge case 全通过。

## 4. 测试重点

### 4.1 状态机测试

覆盖：

- 草稿到审核。
- 审核通过到待开始。
- 待开始到拍卖中。
- 拍卖中到待家长确认。
- 待家长确认到待交付确认。
- 待交付确认到已完成。
- 任意异常路径到已取消、流拍或已下架。
- 社区/分类暂停时，未开始、拍卖中、待确认、待交付场次按规则收口。
- 注销申请遇到活跃拍卖、有效冻结或未结申诉时被阻断。

### 4.2 积分账本测试

覆盖：

- 初始发放。
- 出价冻结。
- 被超越解冻。
- 撤销解冻。
- 成交完成转移。
- 取消退回。
- 管理员调整。
- 冲正记录。
- 快照与流水重算一致。

### 4.3 并发测试

覆盖：

- 同一拍品多人同时出价。
- 同一孩子对多个拍品同时出价。
- 出价和拍卖结算同时发生。
- 撤销和新出价同时发生。
- 队列重复触发结算。
- 最后一个邀请码名额被多人同时使用。
- outbox 事件重复领取、worker 崩溃和租约过期后重试。

### 4.4 权限测试

覆盖：

- 未绑定家长的孩子不能发布、出价、成交。
- 未加入社区不能浏览、搜索、出价。
- 家长只能管理自己的孩子。
- 活动管理员只能处理自己社区。
- 平台管理员可复核全平台事项。
- 卖家孩子不能对自己的拍品出价。
- 同一主监护人名下孩子默认不能互拍。
- 账号、社区成员、分类或平台暂停时，服务端拒绝对应写操作。
- 副监护人不能覆盖主监护人的有效拒绝或关键限制。

### 4.5 隐私与内容测试

覆盖：

- 图片出现儿童、人脸、姓名、地址、二维码时拦截或进入高风险。
- 禁售品类拦截。
- 文本联系方式拦截。
- 未审核图片不可公开访问。
- 孩子端不可见原价金额、家长手机号、地址、快递信息。
- 已上架内容编辑后必须生成新版本并重新审核。
- 高风险和严重风险不能由活动管理员单人放行。

### 4.6 生产 edge case 回归

覆盖：

- 自买自卖、同家庭互拍、刷分和求购响应绕过互拍限制。
- 主/副监护人对成交确认和交付确认做出冲突决定。
- 社区暂停、分类暂停、暂停出价、暂停成交结算对活跃拍卖和冻结积分的影响。
- 内容安全 API 超时、失败、重复回调和返回不可解析。
- 账号限制、成员移除和注销申请遇到未完成交易或有效冻结。
- 起拍积分、最小加价、出价金额为 0、负数或超过平台上限。
- 管理员已有出价后调整结束时间的通知、次数和审计约束。

## 5. 试点指标

### 5.1 增长与参与

- 注册孩子数。
- 绑定家长数。
- 加入社区成功率。
- 拍品提交数。
- 求购提交数。
- 出价数。
- 收藏/关注数。

### 5.2 闭环效率

- 审核通过率。
- 平均审核时长。
- 成交率。
- 流拍率。
- 家长确认通过率。
- 交付完成率。
- 平均成交完成时长。

### 5.3 安全治理

- 取消率。
- 申诉率。
- 违规率。
- 下架率。
- 禁售命中数。
- 儿童隐私风险命中数。
- 严重儿童隐私泄露事件数。
- 积分账本异常数。
- 审核积压量。

## 6. 暂停条件

必须设为硬门槛：

- 严重儿童隐私泄露：立即暂停相关社区或全平台发布/展示。
- 积分账本异常：立即暂停出价、成交和积分转移。
- 投诉、申诉、取消率超过阈值：暂停扩容，进入复盘。
- 审核积压严重：暂停新发布或限制发布频率。
- 违规物品高发：加严规则或暂停相关分类。

所有暂停和恢复都必须由平台管理员记录原因。

## 7. 上线前检查清单

- PRD、架构、数据模型完成评审。
- 法务完成用户协议、隐私政策、儿童信息保护规则复核。
- 所有核心状态机有测试。
- 积分账本并发和重算测试通过。
- Web 管理后台危险操作全留痕。
- 未审核图片无法公开访问。
- 内容版本、监护人决策、治理开关、outbox 租约和邀请码并发测试通过。
- 订阅消息模板配置完成。
- 暂停开关演练完成。
- 试点社区、管理员和家长说明材料准备完成。

## 8. 非 MVP 后续方向

- 更细品类体系。
- 更完善的相似度搜索和同义词词库。
- 活动方脱敏统计报表。
- 更细的管理员角色分层。
- 快递交付风控增强。
- 内容安全模型自有样本评估。
- 更大规模社区运营机制。
- 在合规审查通过后评估是否接入支付或押金，但当前不作为路线图目标。
