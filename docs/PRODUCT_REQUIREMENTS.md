# 产品需求文档

## 1. 产品定位

本产品是一个面向小学 3-4 年级儿童的微信积分拍卖小程序。孩子可以在家长监护下提交自己想卖的物品、发布想买的需求，并用平台积分参与拍卖。平台不处理人民币支付，不展示或记录线下补差价。

产品不是开放二手交易平台。它是带有邀请码、家长授权、活动管理员审核、平台治理能力的开放拍卖社区。

## 2. 核心原则

- 孩子是参与者，不是独立交易主体。
- 家长承担监护、确认、限制、申诉和交付确认职责。
- 活动管理员负责成员、内容和一线纠纷处理。
- 平台管理员负责社区准入、抽检、复核、严重违规、积分处置和平台级治理。
- 积分只是平台内竞拍媒介，不等同人民币，不能充值、提现或系统外转让。
- 平台不承诺商品质量、线下补差价、家长自行约定交付、快递丢损等履约结果；平台仍承担审核、未成年人保护、儿童信息保护、投诉举报和违规处置等治理责任。
- 生产裁决默认失败关闭：时间、权限、审核、积分、文件访问、搜索可见性或通知状态不确定时，不展示、不成交、不转积分。

## 3. 术语

| 术语 | 定义 |
| --- | --- |
| 拍卖社区 | 由机构或社区组织者申请创建、平台审核通过后开放的社区空间，可使用邀请码加入。 |
| 拍品 | 孩子提交的一件待拍卖物品。 |
| 拍卖场次 | 围绕一件拍品的一次固定时间竞拍。 |
| 求购 | 孩子提交的“我想买”需求。 |
| 求购响应 | 其他孩子表示“我有这个”的响应，审核通过后转成普通拍品/拍卖场次。 |
| 积分 | 平台内通用竞拍积分，每个孩子一个全局账户。 |
| 冻结积分 | 当前最高出价占用的积分，成交完成、被超越、撤销或取消后按规则转移或释放。 |

## 4. 角色

| 角色 | 核心权限 |
| --- | --- |
| 孩子 | 提交拍品、提交求购、响应求购、出价、收藏/关注拍品。 |
| 主监护人 | 绑定/解绑、关键授权、设置限制、成交确认、交付确认、申诉、积分申请、注销孩子账号。 |
| 副监护人 | 查看行为、协助确认交易，不能移除主监护人。 |
| 社区创建者/机构管理员 | 申请创建拍卖社区，配置社区规则、邀请码、管理员和交付选项。 |
| 活动管理员 | 审核成员、拍品、求购、响应；处理一线申诉和交付异常。 |
| 平台管理员 | 审核社区创建、抽检复核、处理严重违规、全平台限制、积分纠错和最终复核。 |

## 5. 范围

### 5.1 MVP 包含

- 微信登录、家长绑定、孩子档案。
- 拍卖社区创建申请、邀请码、加入审核。
- 孩子提交拍品、求购和求购响应。
- AI 内容安全识别 + 规则引擎 + 人工审核。
- 固定结束时间的英式升价积分拍卖。
- 积分冻结、解冻、成交转移、管理员调整和不可变流水。
- 家长成交确认、交付确认、取消、流拍、撤回、下架、申诉。
- 小程序内通知中心 + 微信订阅消息。
- Web 管理后台。
- 试点指标、暂停条件和审计日志。

### 5.2 MVP 不包含

- 微信支付、平台代收代付、钱包、提现、充值。
- 小程序内记录人民币补差价。
- 孩子之间评论、私信、群聊、联系方式展示。
- 全平台公开搜索未加入社区内容。
- 个性化推荐或儿童画像推荐。
- 自动上架未审核内容。
- 管理员 SQL 控制台。
- 平台裁决线下赔偿、快递丢损或商品真实价值争议。

## 6. 账号与监护

### 6.1 登录入口

- 孩子有微信：孩子微信登录，绑定家长后启用。
- 孩子无微信：家长微信登录，创建孩子档案。
- 每个孩子档案必须绑定至少一个家长。
- 每个孩子最多绑定两个家长：主监护人和副监护人。
- 一个孩子微信只绑定一个孩子档案。
- 一个家长默认最多管理 3 个孩子，超过需审核。

### 6.2 家长校验

第一版使用：

- 微信登录。
- 手机号绑定。
- 监护声明勾选。
- 儿童信息处理授权。
- 隐私政策和用户协议确认。

暂不接身份证、人脸或第三方实名认证，除非后续运营或监管要求强制。

### 6.3 孩子信息最小化

孩子侧只收集：

- 昵称。
- 微信头像，需 AI 审核，风险头像替换为系统默认头像。
- 年龄段/年级。
- 所属社区。
- 绑定家长状态。

默认不收集孩子身份证件、手机号、真实姓名、详细地址或联系方式。

### 6.4 账号安全与监护争议

- 家长账号执行敏感操作前必须二次确认或重新认证，包括成交确认、交付确认、修改孩子权限、导出数据、注销孩子账号、添加/移除副监护人。
- 家长敏感操作应记录设备、登录会话、服务端时间和风险标签；新设备或异常地点登录后进入敏感操作冷却期。
- 家长账号疑似被盗时，平台可暂停该家长管理的孩子出价、发布、成交确认、数据导出和注销。
- 管理员账号必须启用更高强度验证；批量导出、积分处置、社区暂停、强制下架、解除限制等高危操作默认需要平台管理员复核。
- 主监护人和副监护人发生监护权争议、解绑争议、注销争议或家长投诉时，孩子档案进入监护争议冻结模式。
- 监护争议冻结模式下，暂停发布、出价、成交确认、交付方式变更、数据导出和注销；已冻结积分和未完成交易由平台复核收口。
- 家长管理多个孩子时，所有写操作必须显式确认当前孩子档案，不能依赖本地缓存的当前孩子。

## 7. 拍卖社区

### 7.1 创建

社区创建者或机构管理员提交申请，平台审核通过后开放。

申请信息包括：

- 社区名称、简介、邀请码、开放时间。
- 创建者身份信息、机构/组织信息、联系方式。
- 社区规则、禁售补充规则、交付方式、管理员名单。
- 预计参与人数、适用年龄段、活动区域。

创建者默认是活动管理员。正式开放前建议至少配置 2 个活动管理员。

### 7.2 邀请码与加入

- 创建者可设置易记邀请码。
- 系统保证唯一性，并保留内部社区 ID。
- 邀请码可失效、重置、设置有效期和使用次数。
- 邀请码使用次数必须以服务端原子结果为准，不能因并发加入超过上限。
- 加入社区需要：邀请码 + 家长确认 + 活动管理员审核。
- 只有加入成功后，孩子才能浏览、搜索、发布、出价。

### 7.3 积分跨社区

孩子可以加入多个拍卖社区。积分为全平台通用，不按社区隔离。社区可设置是否允许使用平台积分参与，但不能创建独立积分账本。

### 7.4 社区准入与成年人伪装防控

- 邀请码不能作为唯一准入依据；活动管理员必须按社区名单、班级/活动名册或机构确认信息审核成员。
- 首次发布、首次求购响应、短时间大量浏览/收藏/出价、异常夜间活跃、跨社区异常加入等行为进入平台风险监控。
- 疑似成年人伪装孩子、诱导线下联系、收集儿童信息或绕过家长的账号，立即限制发布、出价、搜索和交付能力，转平台复核。
- 社区规则必须版本化；禁售、交付方式、积分奖励或审核规则变更后，需要通知家长并保留规则版本。

## 8. 拍品与求购

### 8.1 拍品字段

- 标题。
- 基础分类：玩具、书籍、文具、运动用品、手工/收藏、其他。
- 描述。
- 新旧程度：全新、几乎全新、轻微使用、明显使用、有破损或缺件。
- 自由瑕疵/缺件说明。
- 原价金额：可填写具体金额，仅家长、活动管理员、平台管理员可见，不公开给孩子端，不作为平台估值。
- 起拍积分。
- 最小加价幅度。
- 至少 4 张图片：正面、背面、侧面、瑕疵/细节。

### 8.2 图片规则

拍品图片只允许展示物品本身。

禁止出现：

- 孩子本人或其他儿童。
- 人脸。
- 校服姓名。
- 证件。
- 作业本姓名/学校信息。
- 家庭地址。
- 电话号码。
- 二维码/微信号。
- 其他可识别个人身份的信息。

### 8.3 求购规则

- 孩子可以提交“我想买”。
- 求购需要 AI 审核和人工审核。
- 其他孩子可以响应“我有这个”。
- 求购响应审核通过后，转成普通拍品/拍卖场次。
- 求购不直接成交，不支持点对点私下撮合。

### 8.4 内容修改与版本

- 拍品、求购、响应、头像和图片在审核通过后若修改公开字段，必须生成新内容版本并重新进入 AI 审核和人工审核。
- 公开字段包括标题、描述、瑕疵说明、图片、分类、交付说明和任何孩子端可见文本。
- 新版本审核通过前，孩子端继续展示上一已审核版本；若无上一已审核版本，则不展示。
- 修改后命中高风险或严重风险时，应立即隐藏当前内容或转平台复核，不能继续依赖旧审核结果。
- 管理员审核记录必须绑定具体内容版本，不能只绑定目标 ID。
- 下架、申诉、举报和审计展示时必须能追溯到当时公开展示的版本。

## 9. 禁售与审核

### 9.1 禁售规则

平台设置基础禁售清单，活动方可以加严但不能放宽。

基础禁售包括：

- 食品、饮料、生鲜、药品、保健品。
- 刀具、仿真枪、危险玩具、化学品、易燃易爆物。
- 成人用品、烟酒、电子烟。
- 活体动物和宠物活体交易。
- 游戏账号、虚拟币、虚拟物品、抽奖/赌博/盲盒类。
- 高价值电子产品、奢侈品、贵金属。
- 侵权盗版、来源不明、违法违规物品。
- 含儿童隐私信息的物品或图片。
- 召回商品、破损电池、磁力珠、小零件高误食风险玩具、尖锐零件、强激光、强磁、可能造成儿童伤害的低价值高风险物品。

### 9.2 审核机制

- 第三方内容安全 API 识别图片和文本风险。
- 平台规则引擎检查禁售分类、关键词、图片数量、原价异常、重复发布、异常出价等。
- 平台规则引擎必须结合 OCR、二维码/条码识别、图片元数据检查、历史版本差异和联系方式变体词检查。
- 所有内容必须人工审核后才能展示。
- AI 只做辅助分流，不作为最终上架裁决。
- 第三方内容安全 API 超时、失败、返回不可解析或结果互相冲突时，内容保持不可展示，不能人工绕过为低风险。
- 人工审核后台必须提供原图放大、OCR 文本、版本 diff、风险标签和历史违规上下文。

### 9.3 AI 风险分流

- 低风险：进入人工审核，附风险提示。
- 中风险：必须人工审核，禁止自动通过。
- 高风险：直接拦截，通知家长和管理员。
- 严重风险：进入平台复核，必要时限制账号或社区。

### 9.4 审核运营风险

- 高风险内容、儿童隐私命中、禁售疑似、首次发布账号、被投诉账号的内容必须双审或平台抽检。
- 审核员连续高强度审核必须有节流和抽检机制，防止审核疲劳导致误放。
- 审核质量应记录误放率、误拒率、复核改判率和严重风险漏放数。
- 恶意投诉、批量投诉、竞争性投诉和重复无证据投诉应限频并纳入违规记录。

## 10. 拍卖规则

### 10.1 基本规则

- 固定结束时间，时间到最高积分者暂定成交。
- 不自动延长，不做一口价。
- 拍卖结束、撤销窗口、确认超时和交付超时全部以服务端/数据库时间裁决，客户端时间只用于展示。
- 服务端时间异常、数据库时间不可用或结算时间无法确认时，拍卖进入待结算处理，不能自动成交。
- 拍卖场次时间由系统按社区默认规则自动生成，例如 24/48/72 小时。
- 活动管理员可调整单个拍品时间，但必须填写原因、记录日志，并对相关家长可见。
- 已有出价后调整结束时间需要更严格确认，平台可复审异常调整。
- 已有出价后，活动管理员不能将结束时间提前到少于 30 分钟后，除非因禁售、隐私泄露或安全风险直接下架。
- 已有出价后，单次延长不得超过社区默认拍卖时长，且必须通知当前最高出价方、卖家家长和关注者。
- 已有出价后的时间调整每日最多 1 次；异常频繁调整进入平台复核。

### 10.2 出价规则

- 每个拍品设置起拍积分和最小加价幅度。
- 新出价必须大于等于当前最高价 + 最小加价幅度。
- 只冻结当前最高出价者的积分。
- 被超越后旧最高出价者积分自动解冻。
- 出价成功以服务端事务结果为准。
- 起拍积分和最小加价幅度必须为正整数，并受平台配置的上限约束。
- 卖家孩子不能对自己的拍品出价。
- 同一主监护人名下的孩子默认不能互相出价；如学校活动确需开放，必须由平台管理员开启社区级例外并纳入异常监控。
- 同一家庭、同一监护手机号、同一微信身份链路或其他高风险关联关系命中的互拍，应拦截或进入平台复核。
- 求购响应转拍品后，同样适用自买自卖和同家庭互拍限制。
- 账号、孩子档案、社区成员、拍品或分类处于限制/暂停状态时，出价必须被服务端拒绝。
- 出价结果不明确、事务超时、锁等待超时或网络重试状态不确定时，客户端必须展示“以刷新后的服务端状态为准”，不能展示成功。

### 10.3 出价撤销

- 只允许撤销自己的当前最高出价。
- 只能在出价后 1 分钟内撤销。
- 每个孩子每日最多撤销 1 次，或每个拍品最多撤销 1 次。
- 撤销后积分解冻，拍卖回退到上一有效最高价。
- 通知上一最高出价者和卖家家长。
- 写入拍品动态和家长可见日志。

### 10.4 拍品撤回

- 无出价：卖家家长可撤回。
- 已有出价：卖家家长申请撤回，活动管理员审核。
- 撤回通过后通知当前最高出价方，解冻积分，并记录原因。

## 11. 状态机

拍品/拍卖场次主状态：

```text
草稿
  -> AI审核中
  -> 人工审核中
  -> 待开始
  -> 拍卖中
  -> 待结算处理
  -> 待家长确认
  -> 待交付确认
  -> 已完成
```

异常终态：

- 已取消：流程性终止，例如撤回、家长拒绝、确认超时、买方/卖方取消。
- 流拍：拍卖结束时没有有效出价。
- 已下架：治理性处置，例如禁售、隐私泄露、虚假图片、投诉成立、管理员强制移除。

`待结算处理` 仅用于暂停成交结算、结算任务失败或人工复核中的到期拍卖；恢复或处理后必须进入待家长确认、流拍、已取消或已下架。

## 12. 成交、交付与纠纷

### 12.1 成交确认

- 拍卖结束后，有最高出价则进入待家长确认。
- 买家冻结积分继续锁定。
- 买家家长和卖家家长并行确认。
- 双方都确认后进入待交付确认。
- 任一方拒绝则取消，买家冻结积分退回。
- 48 小时内未完成确认，自动取消或转管理员处理。
- 每一侧的确认必须记录确认人、监护角色、决定、时间、确认版本和操作来源。
- 主监护人的决定优先级高于副监护人。
- 副监护人先确认后，若主监护人在进入待交付确认前拒绝，则按拒绝处理并取消交易。
- 同一侧监护人出现冲突且无法按主监护人优先规则自动裁决时，交易进入管理员处理，冻结积分继续锁定。
- 交易完成后再发生监护人争议，只能通过申诉和管理员纠错处理，不能直接改写历史确认记录。

### 12.2 交付方式

支持三种方式：

- 活动指定交付点：平台/活动方配置地点和时间，推荐默认项。
- 家长自行约定：只允许家长端操作和确认，不允许孩子看到电话、地址、私聊。
- 快递交付：只允许家长填写；孩子不可见地址；平台不承运、不生成运单、不处理运费，只记录“家长选择快递交付”。

### 12.3 交付确认

- 买卖双方家长都确认后，交易完成。
- 交易完成时，冻结积分从买家转给卖家。
- 交付确认期限建议 72 小时。
- 超时未完成双方确认，转活动管理员处理。
- 任一方家长可提前申请处理。

### 12.4 交付争议

管理员可基于平台内证据处理积分：

- 退回买家。
- 转给卖家。
- 继续冻结等待补充材料。

限制：

- 必须填写处理原因。
- 只能处理平台内状态和积分。
- 不裁决线下赔偿、快递丢损或商品真实价值。
- 家长可申诉，平台管理员可复核。

### 12.5 暂停、限制与交易收口

- 平台暂停新发布时，不影响已进入待家长确认或待交付确认的交易继续处理。
- 平台暂停出价时，所有新出价被拒绝；已冻结积分保持原状态，直到拍卖结算、取消、下架或管理员处理。
- 平台暂停成交结算时，到期拍卖不得自动进入待家长确认，必须保持可追溯的待处理状态，由平台恢复后批量结算或管理员逐单处理。
- 单社区或单分类暂停时，该范围内未开始拍卖不得开始，拍卖中场次默认取消并解冻，除非平台管理员选择只暂停新动作并允许既有场次自然结束。
- 因严重儿童隐私、禁售或安全风险暂停时，相关拍品必须优先下架，当前冻结积分立即退回买家。
- 账号被限制、社区成员被移除或孩子账号申请注销时，必须先处理该孩子的活跃出价、当前最高冻结、待确认交易、待交付交易和未结申诉。

## 13. 积分

### 13.1 账户规则

- 每个孩子一个全局积分账户。
- 家长没有积分账户，只有监管和确认权限。
- 积分不可充值、提现或系统外转让。
- 普通用户之间不能非交易转赠积分。

### 13.2 发放规则

- 孩子首次完成家长绑定后，平台自动发固定初始积分。
- 平台管理员可批量发放、扣减、纠错。
- 家长可提交积分申请，但只限纠错和活动奖励。
- 积分申请必须审核后生效。
- 不允许以缴费、捐赠、购买积分包等方式换积分。

### 13.3 账本规则

- 余额快照包含可用积分、冻结积分和派生统计字段。
- 账本流水不可修改，只能追加冲正记录。
- 发放、冻结、解冻、转移、扣减、纠错都必须入账。
- 所有积分变动必须在数据库事务中同时更新快照和追加流水。

## 14. 家长控制

家长可配置：

- 是否允许孩子发布拍品。
- 是否允许孩子参与竞拍。
- 单次最高出价积分。
- 每日出价次数。
- 每日发布数量。
- 是否允许快递交付。
- 是否允许家长自行约定交付。
- 是否每次出价都需要确认。
- 是否发布前需要家长确认。
- 是否允许收藏/关注。
- 通知范围和提醒频率。

强制规则：

- 高原价、敏感分类、疑似高价值、异常物品强制家长预确认。
- 超过家长设置阈值或系统风险阈值的出价强制家长确认。
- 成交后必须双方家长确认。

## 15. 信用、违规与申诉

- 信用/违规记录全平台通用。
- 买方原因取消、卖方原因取消、恶意撤销、虚假拍品、禁售物品、隐私泄露等进入全平台记录。
- 自买自卖、同家庭异常互拍、刷分、规避审核发布联系方式，按严重违规进入全平台记录。
- 30 天内买方原因取消累计 3 次，暂停出价 7 天。
- 30 天内卖方原因取消累计 3 次，暂停发布 7 天。
- 家长可提交申诉。
- 活动管理员处理普通申诉，平台管理员复核严重违规、全平台限制和家长不认可的结果。

## 16. 搜索、排序与收藏

### 16.1 搜索范围

孩子只能搜索自己已加入社区内的可见内容。不可搜索：

- 未加入社区内容。
- 待审核内容。
- 已下架内容。
- 违规内容。
- 被封禁社区内容。
- 对该孩子或家长不可见的内容。
- 搜索权限必须由服务端按当前成员、内容版本、下架、暂停和限制状态过滤，不能依赖前端隐藏或仅依赖搜索索引。
- 搜索索引延迟、缓存过期或权限状态不确定时，结果必须回源校验；校验失败则不展示。

### 16.2 搜索能力

搜索匹配：

- 拍品标题。
- 拍品描述。
- 分类。
- 新旧程度。
- 求购内容。
- 关键词相似度，例如“乐高”匹配“积木”。

### 16.3 排序

MVP 支持：

- 最新。
- 即将结束。
- 出价最多。
- 热门。
- 分类筛选。

热门排序使用非个性化综合热度：出价次数、浏览次数、收藏/关注次数，同用户重复浏览降权。

热门和排序防刷规则：

- 同用户、同设备、同 IP、同家庭、异常频率浏览/收藏/出价必须降权或剔除。
- 热门排序不得因为刷浏览、刷收藏或异常关注让未审核、下架、风险内容获得曝光。

### 16.4 收藏/关注

孩子可以收藏拍品和关注结束提醒。家长可关闭或限制收藏/关注功能，并查看孩子收藏记录。

## 17. 通知

第一版通知方式：

- 小程序内通知中心：完整记录。
- 微信订阅消息：关键事件提醒。
- 通知和 WebSocket 可能延迟、乱序或重复，只能作为提醒，不能作为交易状态凭据。
- 用户打开通知、回到前台或进入详情页时，必须拉取服务端最新状态后再展示可操作按钮。
- 安全、治理、成交和积分异常通知不可被普通偏好关闭。
- 微信订阅消息不可达、模板失败或用户未授权时，站内待办和页面红点必须继续作为关键流程入口。
- WebSocket 房间权限必须随成员移除、账号限制、家长解绑、社区暂停实时失效；旧连接不能继续收到敏感推送。

默认分层：

- 孩子收到轻量动态：出价被超越、拍卖即将结束、审核结果、拍卖结果。
- 家长收到关键通知：成交确认、交付确认、违规/下架、申诉、积分异常、权限限制、绑定授权。
- 家长可关闭或限制孩子的部分通知。
- 关键安全和治理通知不可关闭。

## 18. 数据导出与注销

- 家长可导出孩子行为记录。
- 平台管理员可导出审计和运营数据。
- 活动管理员第一版不导出明细儿童数据，最多查看脱敏统计。
- 导出文件必须短期有效、私有存储、访问留痕，并按角色脱敏。
- 生产日志、错误栈、审计摘要和通知 payload 不得包含明文手机号、地址、完整姓名、对象存储 key 或快递信息。
- 主监护人可申请注销孩子账号。
- 注销前必须处理完未完成交易、活跃拍卖、有效冻结积分、待审核内容、未结申诉和限制记录。
- 公开资料下线或匿名化，非必要个人信息删除或匿名化。
- 注销、删除和匿名化必须覆盖主库、搜索索引、对象存储、导出文件、日志、审计摘要、缓存、通知 payload 和可恢复备份的保留策略。
- 必要交易、积分账本、审核、违规、申诉记录按规则保留。

## 19. 截图、转发与线下安全

- 展示交付点、家长可见联系方式、快递信息、导出文件、申诉材料和审核证据的页面必须加用户水印或访问标识。
- 孩子端不得出现可被截图传播的家长联系方式、地址、真实姓名、学校班级或快递信息。
- 家长端敏感页面应提示不得外传儿童信息；导出文件必须包含访问者水印和过期时间。
- 平台不裁决商品真实价值，但必须阻断明显儿童安全风险商品，并向家长展示线下交付安全提醒。

## 20. 生产硬门槛

以下场景必须在 MVP 试点前被阻断或失败关闭：

- 客户端时间、通知时间或本地缓存不能影响拍卖、撤销、确认、结算和交付超时裁决。
- 出价、撤销、结算、确认、交付、积分调整遇到事务超时、死锁、锁等待超时或重试状态不明时，不能返回成功。
- Redis、BullMQ、WebSocket、第三方内容安全 API 或搜索索引不可用时，不能影响 PostgreSQL 中的积分、拍卖和交易事实。
- 未审核、已拒绝、已下架、已删除或权限不匹配的文件不能通过旧签名 URL、CDN 缓存、对象 key 或日志继续访问。
- 搜索、热门排序、收藏列表和通知跳转不得暴露未加入社区、已下架、待审核或对当前孩子不可见的内容。
- 管理员下架、取消、解冻、转积分、暂停社区、调整结束时间和批量导出前，必须展示影响预览并二次确认。
- 审核、导出、日志、通知和对象存储链路不得泄露儿童姓名、学校、地址、电话、二维码、微信号、快递信息或家长联系方式。
- 家长或管理员账号疑似被盗时，敏感操作必须被拦截、告警并可撤销会话。
- 管理员越权、活动管理员跨社区查看儿童数据、平台运营无理由导出明细数据必须被服务端拒绝。
- 监护争议、家长解绑争议和注销争议必须进入冻结模式，不得继续交易或导出。
- 备份恢复、数据库迁移、灰度发布或 worker 版本不一致时，不得重复结算、重复转积分或重放已处理 outbox。
- 恶意上传、伪装 MIME、超大图片、压缩炸弹、SVG/脚本文件和带 EXIF 隐私的图片必须被拒绝或转码清理。
- 第三方供应商不可用、权限过大或可能持有儿童数据时，必须降级、最小化传输并纳入供应商审计。

## 21. MVP 验收标准

MVP 必须覆盖：

- 发布到成交的完整拍卖闭环。
- 审核、出价、冻结、成交、确认、交付、积分转移。
- 取消、撤回、流拍、下架、申诉等异常路径。
- 自买自卖拦截、同家庭异常互拍治理、内容修改重新审核、暂停收口、注销阻断等生产边界路径。
- 时间裁决、锁等待/死锁、通知乱序、对象存储泄露、搜索权限泄露、日志导出泄露、管理员误操作等高风险场景。
- 账号盗用、管理员越权、监护争议冻结、备份恢复、迁移发布、恶意上传、截图外泄、第三方供应商和全链路删除等生产治理场景。
- 家长授权、未成年人保护、通知、后台审计。
- 小范围真实试点的指标采集和暂停机制。

## 22. 合规提示

本 PRD 不构成法律意见。上线前需对以下事项进行法务复核：

- 儿童个人信息收集、使用、存储、删除和导出。
- 监护人授权和撤回机制。
- 用户协议、隐私政策、儿童隐私保护规则。
- 网络交易平台责任边界。
- 活动组织者、平台、家长之间的责任划分。
