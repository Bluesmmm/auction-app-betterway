# 技术架构方案

## 1. 架构目标

系统优先保证：

- 积分账本一致性。
- 拍卖状态机可追溯。
- 未成年人内容与隐私治理。
- 管理员操作可审计。
- 小范围试点可观测、可暂停、可回滚。
- 时间、权限、审核、文件访问、搜索可见性和通知状态全部失败关闭。
- 账号安全、管理员安全、备份恢复、发布迁移和第三方供应商默认最小权限、可审计、可回滚。

第一版不追求微服务拆分。核心复杂度在事务一致性、状态流转和治理闭环。

## 2. 技术栈

### 2.1 小程序

- 微信小程序原生。
- 微信登录。
- WebSocket 接收拍卖实时变化。
- 页面进入、恢复前台、出价后通过 REST 拉取最新状态。
- 轻量状态库管理登录态、当前孩子档案、积分摘要、通知红点和 WebSocket 状态。

### 2.2 Web 管理后台

- React。
- Vite。
- TypeScript。
- Ant Design。
- React Router。
- TanStack Query。
- Zod。

后台定位为中后台运营工具，负责社区审核、拍品审核、申诉处理、积分处置、用户限制和日志审计。

### 2.3 后端

- NestJS 模块化单体。
- PostgreSQL 作为唯一业务事实源。
- Redis 用于缓存、限流、防重复点击、WebSocket 辅助和队列支撑。
- BullMQ + Redis 处理延迟任务、异步任务、重试和失败队列。
- 对象存储保存图片。
- 第三方内容安全 API 做文本/图片风险识别。
- 所有业务裁决时间使用 PostgreSQL 或服务端统一时间源，客户端时间只用于展示。

## 3. 高层架构

```text
微信小程序
  -> REST API
  -> WebSocket Gateway

Web 管理后台
  -> REST API

NestJS 模块化单体
  -> PostgreSQL
  -> Redis
  -> BullMQ Workers
  -> 对象存储
  -> 第三方内容安全 API
  -> 微信订阅消息
```

核心事实只以 PostgreSQL 为准。Redis、BullMQ、WebSocket 和第三方审核结果都不能直接裁决拍卖或积分状态。

所有安全敏感读写都必须回到 PostgreSQL 做最终权限和状态校验。缓存、搜索索引、签名 URL、通知 payload 和客户端本地状态都不能作为可见性或交易裁决依据。

## 4. 后端模块

建议模块：

- `AuthModule`：微信登录、token、会话撤销。
- `GuardianModule`：家长资料、手机号、监护授权、主副监护人。
- `SecurityModule`：敏感操作二次验证、设备风险、会话撤销、管理员 MFA 和安全事件。
- `ChildProfileModule`：孩子档案、绑定关系、家长控制项。
- `CommunityModule`：拍卖社区、邀请码、成员申请、社区规则。
- `ItemModule`：拍品、图片、分类、新旧程度、求购和响应。
- `ModerationModule`：AI 审核、规则引擎、人工审核、下架。
- `AuctionModule`：拍卖场次、状态机、结算。
- `BidModule`：出价、撤销、实时推送。
- `PointLedgerModule`：积分账户、冻结、解冻、转移、纠错、账本。
- `TransactionModule`：成交确认、交付确认、取消和完成。
- `NotificationModule`：站内通知、微信订阅消息、通知偏好。
- `AppealModule`：申诉、纠纷处理、复核。
- `AdminModule`：后台权限、运营操作、审计日志。
- `FileModule`：临时文件、正式文件、签名 URL。
- `JobModule`：BullMQ job 注册、重试、失败处理和定时兜底。
- `SearchModule`：搜索索引写入、回源权限过滤和索引延迟兜底。
- `ObservabilityModule`：结构化日志脱敏、指标、告警和审计校验。
- `ReleaseModule`：数据库迁移、灰度发布、版本兼容和回滚检查。
- `VendorRiskModule`：第三方供应商配置、数据最小化、调用审计和降级策略。

## 5. API 风格

- 主体使用 REST API。
- 拍卖出价变化使用 WebSocket 推送。
- 页面进入、恢复前台、出价后必须用 REST 拉取最新状态。
- WebSocket 断开时提示重连，断线期间不能基于本地旧价直接出价。
- 关键写操作使用幂等键，避免重复提交。
- 幂等键必须绑定操作者、目标、动作和请求摘要；同键同摘要返回原结果，同键不同摘要拒绝。
- 所有写 API 必须返回服务端裁决时间、目标版本和最新状态；客户端不能根据本地时间或推送事件自行推导成功。
- 事务超时、锁等待超时、死锁重试耗尽、网络中断或结果不确定时，API 必须返回明确的 pending/unknown 或失败语义，并要求客户端刷新状态。

## 6. 认证与会话

### 6.1 登录

- 小程序调用 `wx.login`。
- 后端换取微信身份并绑定内部用户。
- 后端签发短期 `access token` 和较长期 `refresh token`。
- `refresh token` 可撤销。

### 6.2 会话失效条件

- 用户退出登录。
- 主监护人解绑或关闭孩子账号。
- 账号被限制。
- 孩子账号注销。
- refresh token 被主动撤销。

### 6.3 权限

后端必须强校验：

- 当前用户是否能操作当前孩子档案。
- 孩子是否已绑定家长。
- 孩子是否已加入目标社区。
- 家长控制项是否允许发布、出价、交付方式。
- 操作是否需要主监护人确认。
- 管理员是否拥有当前社区或平台权限。
- 卖家孩子是否与出价孩子相同。
- 出价双方是否存在同一主监护人、同一监护手机号或其他高风险关联关系。
- 账号、孩子档案、社区成员、拍品、分类或平台开关是否处于限制/暂停状态。
- 写操作所基于的内容版本、交易版本或拍卖版本是否仍然有效。
- 当前会话是否通过敏感操作所需的二次验证。
- 管理员角色、社区 scope、数据导出 scope 和高危操作复核状态是否匹配。

### 6.4 账号与管理员安全

- 家长敏感操作必须重新认证或二次确认，并记录设备指纹、会话 ID、IP 哈希、风险标签和服务端时间。
- 新设备、异常地点、短时间多次失败、频繁切换孩子档案、批量导出前必须触发风控或冷却期。
- 管理员账号必须启用 MFA；平台管理员、活动管理员和机构管理员使用最小权限 RBAC。
- 高危后台操作支持双人复核或平台复核，包括积分处置、批量导出、社区暂停、强制下架、解除限制和结束时间调整。
- 账号疑似被盗时，必须能撤销 refresh token、踢出 WebSocket 连接、暂停敏感操作并通知家长或平台管理员。
- WebSocket 连接必须定期刷新权限；成员移除、家长解绑、账号限制、社区暂停时要移出相关房间。

## 7. 数据访问策略

- 普通 CRUD、列表、后台配置使用 Prisma。
- 出价、冻结、解冻、成交、取消、管理员积分处置等关键路径由后端代码使用受控 SQL 或 Query Builder。
- 管理员后台永远不开放 SQL 控制台。
- 数据库约束、事务和审计由后端统一保证。
- 关键路径必须包含事务、行级锁、权限校验、幂等检查和审计日志。
- 邀请码消耗必须在事务内锁定 `community_invite_codes` 行，校验状态、有效期和剩余次数后原子递增。
- 积分、起拍价、加价幅度和出价金额必须使用整数类型，并通过数据库 `CHECK` 约束限制为正数和平台上限内。
- 存在多账户锁定时，按账户 ID 固定顺序加锁，降低并发出价、撤销和结算之间的死锁概率。
- 关键事务必须配置 `lock_timeout`、`statement_timeout` 和死锁重试策略；重试仍失败时不得返回业务成功。
- 关键事务写入的审计、账本和 outbox 必须同事务提交；事务外失败只能补偿通知，不能补写业务事实。
- 业务时间字段由服务端或数据库生成；禁止客户端提交裁决用时间。

## 8. 出价并发控制

真正裁决点是 PostgreSQL 事务。

一次出价事务应：

1. 锁定 `auction_sessions` 行。
2. 使用数据库/服务端时间校验拍卖状态、结束时间、当前最高价和最小加价。
3. 校验出价资格：已加入社区、家长控制允许、未被限制、非卖家本人、非默认禁止的同家庭互拍。
4. 如存在旧最高出价者，按账户 ID 固定顺序锁定新旧最高出价者积分账户。
5. 如无旧最高出价者，锁定新最高出价者积分账户。
6. 解冻旧最高出价者积分。
7. 冻结新最高出价者积分。
8. 写入出价记录。
9. 更新拍卖当前最高价、最高出价者和最高出价记录。
10. 写入积分账本流水。
11. 写入审计日志和 outbox 事件。
12. 事务提交后推送 WebSocket 和通知。

出价事务失败处理：

- `lock_timeout`、死锁、连接中断或幂等结果不明时，客户端必须通过 REST 重新拉取拍卖和账户状态。
- 服务端不得在未确认事务提交的情况下返回出价成功。
- 同一孩子快速点击、弱网重试和小程序恢复前台后的重复提交，必须由幂等键和最新状态校验共同处理。

Redis 只用于限流、防重复点击和热点保护，不作为最终锁和账本事实源。

## 9. 积分账本架构

积分系统使用：

- 余额快照表：快速查询可用积分、冻结积分和统计字段。
- 不可变账本流水：记录所有发放、冻结、解冻、转移、扣减、纠错。

规则：

- 流水不可更新、不可删除，只能追加冲正记录。
- 账户快照和账本流水必须同事务更新。
- 账户余额不能为负。
- 所有管理员调整必须有原因、操作者和审计日志。
- 定期运行账本校验任务，核对快照和流水汇总。

## 10. 拍卖结束机制

采用延迟队列触发 + 定时扫描兜底：

- 拍品审核通过后创建拍卖结束延迟任务。
- BullMQ 到点触发结算。
- 定时扫描过期未结算拍卖，处理漏执行或失败任务。
- 结算逻辑必须幂等。
- 结算时锁定拍卖场次。
- 无有效出价则流拍。
- 有最高出价则进入待家长确认，最高出价积分继续冻结。
- 结算后写 outbox 事件并发送通知。
- BullMQ 延迟、Redis 故障或 worker 停止时，定时扫描必须在 PostgreSQL 中发现并补偿到期拍卖。
- 服务端时间异常或无法确定是否到期时，拍卖进入 `pending_settlement`，不得自动成交。

## 11. 队列与异步任务

队列技术：BullMQ + Redis。

适用任务：

- 拍卖结束。
- 家长确认超时。
- 交付确认超时。
- 通知发送。
- AI 审核任务。
- 图片转正式存储。
- 数据导出。
- 审计校验。

架构纪律：

- 队列只触发流程，不裁决业务事实。
- 所有 job handler 必须幂等。
- 失败任务进入失败队列并告警。
- 定时扫描兜底关键任务。
- Redis 或 BullMQ 不可用时，API 仍可读取 PostgreSQL 事实；新发布、出价或结算可按功能开关降级暂停。
- Redis 缓存不得缓存最终权限结论；任何缓存命中都必须受版本号、状态和短 TTL 约束。
- worker 恢复后必须能从 PostgreSQL 的待处理状态和 outbox 继续补偿。
- 备份恢复后必须进入恢复模式：暂停出价和结算，运行账本重算、冻结积分核对、outbox 去重和未完成交易扫描。
- 恢复模式退出前，必须确认不会重复结算、重复转积分或重复发送关键通知。

## 12. 图片与内容审核链路

流程：

1. 小程序端本地压缩图片。
2. 上传到临时私有对象存储。
3. 创建文件记录和审核任务。
4. 第三方内容安全 API 审核图片和文本。
5. OCR、二维码/条码识别、图片元数据检查和联系方式变体识别。
6. 平台规则引擎生成风险标签。
7. 活动管理员人工审核。
8. 审核通过后转正式私有/受控存储。
9. 正式图片通过受控访问或签名 URL 展示。

未审核或拒绝图片不能公开 CDN 暴露。

审核容错规则：

- 第三方内容安全 API 超时、故障或返回不可解析结果时，任务保持未通过状态，不能自动上架。
- 高风险和严重风险不得由活动管理员单人放行，必须进入平台复核。
- 人工审核必须绑定具体内容版本；内容修改后创建新版本和新审核任务。
- 新版本审核通过前，孩子端只能访问上一已审核版本；没有上一版本时不展示。
- 审核 worker 重试耗尽后进入失败队列并告警，平台管理员只能在补充人工证据后处理。
- 人工审核页面必须展示原图、缩略图、OCR 文本、二维码检测结果、图片元数据、版本 diff 和历史违规上下文。
- 图片上传后必须清理 EXIF/元数据；原始文件仅在私有存储保留并限制访问。
- 上传文件必须执行 MIME sniffing、大小限制、像素限制、图片转码、恶意 SVG/脚本拒绝、压缩炸弹防护和病毒/恶意内容扫描。
- 第三方内容安全调用只发送审核所需最小数据，不发送儿童真实身份、家长联系方式或不必要上下文。

文件访问规则：

- 临时文件、未审核文件、拒绝文件和下架文件永远不能公开 CDN 暴露。
- 签名 URL 必须短期有效，绑定文件、用户、用途和过期时间；过期后必须回源重新鉴权。
- 下架、删除、注销或权限变更后，旧签名 URL 必须失效或在访问网关被拒绝。
- 生产日志、错误栈、通知 payload 和审计摘要不得记录明文对象 key、签名 URL、地址、手机号或快递信息。

## 13. WebSocket 设计

推送对象：

- 正在看该拍品详情页的人。
- 收藏/关注该拍品的人。
- 相关孩子的家长。
- 相关活动管理员和平台管理员。

不向全社区所有在线成员广播。

推送事件：

- 当前价变化。
- 出价被超越。
- 出价撤销。
- 拍卖结束。
- 成交待确认。
- 状态变更。

所有推送只作为提示，客户端必须以 REST 查询结果为准。

乱序处理：

- 每个推送事件必须携带业务版本、服务端事件时间和事件 ID。
- 客户端收到旧版本、重复事件或乱序事件时只更新提示，不更新裁决状态。
- 从通知跳转、页面恢复前台、WebSocket 重连后必须强制 REST 拉取最新状态。
- 连接加入房间前必须校验当前用户、孩子档案、社区成员和目标内容可见性；权限变化后必须主动踢出房间。

## 14. 通知与 Outbox

建议引入 `outbox_events` 表：

- 关键事务内写业务状态和 outbox 事件。
- 事务提交后由 worker 读取 outbox 发送 WebSocket、站内通知和微信订阅消息。
- 发送失败可重试。
- 避免事务提交成功但通知丢失，或通知发出但状态未提交。
- outbox 事件必须有业务幂等键，消费者必须按事件 ID 或业务键去重。
- worker 获取事件时使用短租约或 `SKIP LOCKED`，记录 `locked_at`、`locked_by` 和下次重试时间。
- 卡在 processing 且租约过期的事件必须能被重新领取。
- 消费者必须容忍重复、乱序和延迟事件；发送通知前回源校验接收人权限和目标最新状态。
- 站内通知保存完整记录，但通知正文不得包含敏感明文；详情页通过权限校验后再展示。

## 15. 管理后台能力

后台功能：

- 社区创建申请审核。
- 邀请码和社区规则管理。
- 成员加入审核。
- 拍品、求购、响应审核。
- AI 风险标签和人工审核记录查看。
- 拍卖时间调整。
- 下架、取消、撤回审核。
- 申诉和交付争议处理。
- 积分发放、扣减、纠错。
- 用户限制和解封。
- 审计日志查询。
- 试点指标看板。
- 危险操作影响预览。

后台所有危险操作必须：

- 二次确认。
- 填写原因。
- 展示影响预览，包括受影响拍卖、冻结积分、交易、通知对象和可回滚动作。
- 写入审计日志。
- 对影响方可见或可追溯。
- 对积分转移、批量导出、社区暂停、强制下架和结束时间调整，必须支持平台管理员复核或冷却期。
- 后台所有列表、详情、搜索、导出、预览和审计查询都必须执行服务端 RBAC 和 scope 校验。
- 审核后台必须支持双审、抽检、误放/误拒统计和审核员质量指标。
- 投诉和申诉必须有频率限制、证据要求和恶意投诉标记。

## 16. 安全与治理

必须实现：

- RBAC 权限控制。
- 操作审计日志。
- 敏感字段最小化展示。
- 孩子端不展示电话、地址、真实姓名、家长信息。
- 内容审核前不公开展示。
- 管理员导出受限。
- 关键 API 限流。
- 出价防重复提交。
- 文件签名访问。
- 账号限制和社区暂停能力。
- 搜索和列表查询必须服务端回源校验可见性，不能只依赖搜索索引或前端隐藏。
- 结构化日志必须默认脱敏，禁止输出明文手机号、地址、姓名、微信号、二维码内容、对象 key、签名 URL 和快递信息。
- 数据导出必须私有存储、短期有效、访问留痕、按角色脱敏，并支持过期删除。
- 敏感页面和导出文件必须带访问者水印、访问时间或追踪标识。
- 注销/删除/匿名化必须覆盖主库、搜索索引、对象存储、缓存、通知、导出文件和日志保留策略。
- 供应商调用必须有数据最小化、超时、重试、降级、权限边界、调用审计和密钥轮换。

## 17. 可观测性

关键指标：

- 积分账本异常数。
- 账户快照与流水汇总差异。
- 出价事务失败率。
- 拍卖结算延迟。
- 队列失败数。
- WebSocket 断连率。
- 审核队列积压。
- 平均审核时长。
- 下架率、申诉率、取消率。
- 儿童隐私风险命中数。
- 严重隐私事件数。
- 数据库锁等待和死锁重试次数。
- 幂等冲突和未知结果次数。
- 签名 URL 拒绝访问次数。
- 搜索回源权限拒绝次数。
- 敏感字段脱敏拦截次数。
- 管理员 MFA 覆盖率。
- 敏感操作二次验证失败率。
- WebSocket 权限踢出次数。
- 审核误放率、误拒率和复核改判率。
- 恶意投诉命中数。
- 备份恢复演练时长和恢复后账本差异。
- 数据库迁移回滚演练结果。
- 第三方供应商调用失败率和敏感字段发送拦截数。

关键告警：

- 账本不平。
- 拍卖结束任务积压。
- 高风险内容审核积压。
- 出价错误率异常。
- 大量撤销或取消。
- 严重隐私风险。
- 死锁或锁等待超时异常升高。
- 未审核文件访问尝试。
- 搜索权限回源拒绝异常升高。
- 日志或导出敏感字段扫描命中。
- 管理员高危操作异常。
- 疑似账号盗用或异常设备登录。
- 审核误放或严重风险漏放。
- 备份恢复后账本不平或 outbox 重放风险。
- 灰度发布版本不兼容。
- 第三方供应商异常或越权调用。

## 18. 暂停与回滚

上线前必须实现平台级开关：

- 暂停新发布。
- 暂停出价。
- 暂停成交结算。
- 暂停单个社区。
- 暂停单个分类。
- 禁用快递交付。
- 禁用家长自行约定交付。
- 强制所有拍品平台复核。

暂停收口规则：

- 暂停新发布：拒绝新拍品、求购和响应；审核中内容继续审核但不自动上架。
- 暂停出价：拒绝新出价和撤销以外的竞拍动作；已有冻结按既有拍卖状态处理。
- 暂停成交结算：到期拍卖标记为待结算处理，恢复后由幂等结算任务补偿。
- 暂停单社区或单分类：未开始场次不再开始；拍卖中场次默认取消并解冻，平台管理员可选择只暂停新动作并允许既有场次自然结束，选择和原因写审计。
- 严重隐私、禁售或安全风险：优先下架相关内容、取消关联场次、解冻买家积分，并通知家长和管理员。
- 账号限制或注销申请：阻断新动作，并检查活跃出价、有效冻结、待确认交易、待交付交易、未结申诉后再允许关闭。

出现以下情况时立即暂停对应能力：

- 严重儿童隐私泄露。
- 积分账本异常。
- 投诉/申诉/取消率超过阈值。
- 审核严重积压。
- 违规物品高发。

## 19. 部署建议

MVP 试点环境至少包含：

- 小程序正式版/体验版。
- Web 管理后台。
- NestJS API 服务。
- 独立 worker 进程。
- PostgreSQL。
- Redis。
- 对象存储。
- 日志、指标和告警。
- NTP/时间同步监控。
- 对象存储私有访问网关或签名 URL 服务。
- 脱敏日志和导出文件过期清理任务。

建议环境：

- `dev`：开发联调。
- `staging`：试点前验收。
- `prod`：真实试点。

生产发布必须支持数据库迁移回滚策略、功能开关和后台暂停操作。

发布和灾备纪律：

- 数据库迁移必须采用 expand/contract 或兼容迁移策略，确保旧 API、旧 worker 和新 schema 可短期共存。
- 新状态枚举、约束、索引和关键字段上线前必须完成 staging 迁移、回滚和数据修复演练。
- 灰度发布期间，API、worker、后台和小程序必须通过功能开关避免双版本同时裁决同一业务事实。
- 备份恢复演练必须覆盖账本重算、冻结积分核对、outbox 去重、搜索索引重建、对象存储权限复核和导出文件过期清理。
- 密钥、对象存储凭证、第三方 API 凭证和管理员 MFA 恢复码必须支持轮换和泄露应急。
